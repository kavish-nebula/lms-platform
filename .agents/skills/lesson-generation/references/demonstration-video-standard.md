# Narrative demonstration video standard

The creator selected the 3:40 Avyana/ECI reference supplied on 17 November 2026 as the visual direction for new topic videos and regeneration of existing generated videos. The reference is visual inspiration; its promotional and healthcare claims are not course teaching sources.

## What to carry forward

- Tell one coherent story: relevant problem, visible task, explanation of the mechanism, checked outcome and transfer recap.
- Illustrate the narrated nouns and verbs. A message arrives, a condition checks it, a document is inspected, an exception branches or a reviewed item changes state. A full explanatory paragraph on screen is insufficient.
- Use the learner's field in the example artifacts and workflow, not only in the title. Keep the technical source example separately identified where assessment coverage depends on it.
- Select an appropriate treatment for each topic: a realistic fictional workspace, annotated document, conversation, process journey, mechanism animation, comparison or source-supported chart. Do not force every topic through a three-box flow or network icon.
- Keep a consistent visual identity with clear headings, restrained depth, readable contrast and purposeful transitions. Use zoom/spotlight only when it helps the learner inspect something. Avoid long brand intros for individual topics.
- Reveal changes at exact spoken phrase anchors, using measured audio timing. Hold states long enough to read. If adjacent statements are too close, introduce related layers together or omit a redundant cue rather than accelerate the animation. Retain a static/reduced-motion path and captions.
- Prefer meaningful state changes over perpetual decorative animation. Keep documents, characters and the example case consistent across related scenes; revisiting them for comparison is useful, replaying the same explanation is not.
- Use supplied or generated visual assets only when they improve teaching and have a validated provenance. Label fictional data. Never invent measurements, UI capabilities or model accuracy to make a demonstration look realistic.

## Production handoff and acceptance

For each video, identify the objective, source evidence, fictional case, visible artifacts, sequence of actions, narration anchors, expected on-screen state and midpoint teaching boundary. Keep these notes outside the course package unless its schema supports them.

Review actual rendered frames and playback: are the artifacts readable, actions matched to speech, layouts varied for a reason, and the final distinction or skill clear? Preserve the seven-minute limit and two-question midpoint checkpoint. The reference's tiny interface labels and promotional claims should not be copied into learning videos. Report render/audio failures; a script or queued job is not a completed video.
